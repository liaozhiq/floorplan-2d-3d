# 户型数据文件说明（layout JSON）

配套文件：

- [layout-4br-2lr-2ba.json](layout-4br-2lr-2ba.json) —— 四室两厅两卫示例（校验通过）
- [validate-layout.mjs](../tools/validate-layout.mjs) —— 校验器
- [源码导读.md](源码导读.md) —— 代码结构（§4 数据模型、§9 扩展点）

```bash
node tools/validate-layout.mjs docs/layout-4br-2lr-2ba.json
```

---

## 1. 它是什么

当前 `index.html` 把户型写死在常量里（`WALLS` / `WINS` / `DOORS` / `SLIDES` / `ROOMS` / `MATS` / `BOUNDS` / `renderDims` 的尺寸链）。
这份 JSON 是**同一组数据的可编辑形态**：字段一一对应，能用几行代码还原成现有常量，因此可以作为「换一套户型」的唯一输入。

单位统一 mm；原点在**左上角内墙面**（左侧外墙内皮 `x=0`、顶部外墙内皮 `y=0`），`x` 向右、`y` 向下，与代码里的平面坐标系完全一致。

---

## 2. 字段对照表

| JSON | 对应代码 | 说明 |
|---|---|---|
| `envelope {w,h}` | — | 内墙面净尺寸，只用于校验和画尺寸链 |
| `bounds {x,y,w,h}` | `BOUNDS` | 2D 视口适配范围，比外包络各留约 1.5 m 余量 |
| `defaults.wallHeight` | `H`（3D，单位 m） | 层高，默认 2800 |
| `defaults.planScale` | `$('#s60')` / `setRatio(60)` | 原图比例 |
| `walls[]` | `WALLS` | `{x0,y0,x1,y1,t}` → `[x0,y0,x1,y1,t]` |
| `wins[]` | `WINS` | `[x0,y0,x1,y1]`，结构与代码相同 |
| `doors[]` | `DOORS` | 结构完全相同，见 §3.2 |
| `slides[]` | `SLIDES` | 结构完全相同 |
| `rooms[]` | `ROOMS` | 结构完全相同，见 §3.3 |
| `mats` | `MATS` | 同上，可直接替换或保留现有 8 种 |
| `dimChains[]` | `renderDims()` 里的 `chain(...)` | `{dir,at,start,segs}` → `chain(dir==='h', at, start, segs)` |
| `furniture.items` | `defaultFurniture()` / `F()` | 需要补 `id`（`uid()`）与缺省 `color`（`typeColor(type)`） |

还原成常量的写法示例：

```js
const WALLS  = L.walls.map(w => [w.x0, w.y0, w.x1, w.y1, w.t]);
const WINS   = L.wins;
const DOORS  = L.doors;
const SLIDES = L.slides;
const ROOMS  = L.rooms;
const MATS   = L.mats;
const BOUNDS = L.bounds;
```

## 3. 关键字段语义

### 3.1 墙体 `walls[].t`

| 值 | 含义 | 平面颜色 | 可拆 |
|---|---|---|---|
| `b` | 承重墙 | 黑（开图层时红棕） | ✗ |
| `e` | 外墙 | 灰 | ✗（仅提示不建议） |
| `n` | 非承重隔墙 | 中灰 | ✓ |
| `low` | 矮墙 | 米色描边 | ✓ |

外墙厚 240、内墙厚 200 是本示例的取值；墙体矩形**压在内墙面之外**（例如顶部外墙是 `y: -240 → 0`）。

### 3.2 门 `doors[]`

```json
{ "name": "主卧门", "rect": [4200,4000,5000,4200], "h": [4200,4200], "c": [1,0], "o": [0,-1], "len": 800 }
```

| 字段 | 含义 | 规则 |
|---|---|---|
| `rect` | 洞口矩形 | 长边 = `len`，短边 ≤ 400（贴墙厚） |
| `h` | 铰点 | 必须是 `rect` 的**四个角之一** |
| `c` | 关门方向 | 轴向单位向量，沿**墙线**方向 |
| `o` | 开门方向 | 轴向单位向量，与 `c` **垂直**，指向门扇打开后所在的一侧 |
| `len` | 门扇长度 | 等于洞口长边 |
| `entry` | 入户门 | 可选，2D 用红色、3D 用深木色门扇并画入户箭头 |

记住一条：**横墙的 `c` 是 `[±1,0]`，竖墙的 `c` 是 `[0,±1]`**；`o` 反过来。

### 3.3 房间 `rooms[]`

```json
{ "id": "master", "name": "主卧", "poly": [[3000,0],[6400,0],[6400,4000],[3000,4000]], "mat": "wood", "at": [4700,2000] }
```

| 字段 | 含义 |
|---|---|
| `id` | 唯一键，`state.rooms[id]` 用它存「改名 / 换地面材料」 |
| `poly` | 内墙面多边形（示例与校验器只支持**轴对齐矩形**） |
| `mat` | 地面材料键，必须在 `mats` 里 |
| `at` | 房间名标签位置，必须在多边形内 |
| `counted` | 省略或 `true` 计入面积；`false` 用于飘窗（示例未使用） |

## 4. 从一张图做出这份 JSON 的流程

1. **定原点与总尺寸**：找到外墙内皮，量出 `envelope.w / h`。图上若无标注，必须先问清一个基准长度，否则整套尺寸都是猜的。
2. **排网格线**：把所有横向、纵向的墙线位置列出来（本示例是 `x: 2800|3000, 6400|6600, 8600|8800, 12000` 这类成对值 = 墙的两个面）。
3. **填 `rooms`**：每个房间用两条 x 线 + 两条 y 线夹出矩形，先不管墙。
4. **填 `walls`**：房间之间的缝就是墙。把每段墙写成矩形，**遇到门窗洞口就断开**——墙列表里不留洞口，洞口由 `doors`/`wins`/`slides` 提供。
5. **填 `doors`/`wins`/`slides`**：洞口矩形要正好填满墙的断口。
6. **填 `dimChains`**：照图纸上的尺寸标注原样抄成分段数组，和必须等于 `envelope`。
7. **跑校验器**，按报错修到 0 error。
8. **填 `furniture`**（可选）：`type` 必须是 `LIB` 里已有的 45 种之一。

---

## 5. 校验器检查什么

| 编号 | 检查 | 常见修法 |
|---|---|---|
| 1 | 墙是正矩形、类型码合法 | 检查 `x1>x0`、`y1>y0` |
| 2 | 房间是轴对齐矩形、面积为正、在包络内 | 用 `rectOfRoom` 的逻辑对齐顶点 |
| 3 | 房间之间不重叠 | 通常是某条墙线少写了墙厚 |
| 4 | 房间内部不被墙/窗/门占用 | 房间多边形要取**内墙面**，不是墙中线 |
| 5 | 每条房间边被「墙∪窗∪门∪推拉门」完整覆盖 | 报「漏缝」= 有段墙没写或洞口对不上 |
| 6 | 门洞：`len` = 长边、铰点在角上、`c⊥o`、不被墙压住 | 洞口矩形必须正好是墙的断口 |
| 7 | 推拉门朝向与 `v` 一致、不被墙压住 | `v:true` 表示竖向（洞口高 > 宽） |
| 8 | 尺寸链之和 = 声明总长 = 包络边长 | 分段数字抄错 |
| 9 | 家具 `type` 在 `LIB` 里、中心点在房间内 | 仅提示，不阻断 |

第 5 项是最有用的一条：它保证**没有任何一面墙漏画**，也就是 3D 里不会出现"能从墙缝看到外面"的情况。

## 6. 示例数据概况

四室两厅两卫，内墙面 12000 × 11000 mm，套内 **120.04 m²**：

| 房间 | 面积 | 房间 | 面积 |
|---|---|---|---|
| 主卧 | 13.60 | 客厅 | 24.00 |
| 次卧 | 11.20 | 餐厅 | 8.64 |
| 儿童房 | 12.80 | 厨房 | 7.20 |
| 第四卧 | 10.80 | 过道 | 6.80 |
| 主卫 | 4.40 | 客卫 | 4.50 |
| 衣帽间 | 3.20 | 阳台 | 9.00 |
| 生活阳台 | 3.90 | | |

40 段墙 / 11 扇窗 / 10 樘平开门 / 2 樘推拉门 / 13 间房。

> 这是**示例**：尺寸按常规四居室推演，用于演示数据结构与填写方式。换成真实图纸时，只需按标注替换数字，其余字段不动。

## 7. 目前的限制

1. 只支持**轴对齐矩形**房间。原项目的 `餐厅`、`过道`、飘窗是 L 形多边形；若要用 L 形，需把校验器第 2 项放宽（房间重叠与覆盖检查仍可保留，但要改成逐边计算）。
2. 未覆盖 `counted:false` 的飘窗台（3D 里会做成抬高 450 mm 的台面），示例中没有飘窗。
3. 这份 JSON 目前**还没有被代码读取**——`index.html` 仍使用内置常量。要真正生效，需要按 [源码导读.md](源码导读.md) §9 的扩展点做一次数据层改造。
