# 户型库：按需生成（0–5 室）

应用内的「文件 ▾ → 户型库…」读的是 **`layouts/index.json`**。这个索引不是固定的 —— **你想看几室，就生成几室**，生成一次覆盖一次。

> 默认已生成 **4 室（172 套，2.3 MB，实测）**，开箱即用。

---

## 1. 一条命令

```powershell
cd D:\hy\floorplan-3d

node tools/layouts-build.mjs 4 --clean     # 四室（默认，≈3 MB）
node tools/layouts-build.mjs 3 --clean     # 三室（≈12 MB）
node tools/layouts-build.mjs 2 --clean     # 二室（≈21 MB）
node tools/layouts-build.mjs 1 --clean     # 一室（≈25 MB）
node tools/layouts-build.mjs 0 --clean     # 零室／开间（≈28 MB，建议配 --top）
node tools/layouts-build.mjs 5 --clean     # 五室（≈0.2 MB）
```

`--clean` 会先清掉 `layouts/` 下旧的几何文件，避免换套数后残留。**不加也行**，但旧的会留着占空间、且索引里不会列它们。

### 各套数的规模（实测 + 估算）

| 室 | 库里可选套数 | 几何体积 | 建议 |
|---|---|---|---|
| 0 | 1574 | ≈21 MB | 太多，建议 `--top=200` |
| 1 | 1411 | ≈19 MB | 同上 |
| 2 | 1153 | ≈15 MB | 可用 |
| 3 | 660 | ≈9 MB | 可用 |
| **4** | **172** | **2.3 MB（实测）** | **默认，推荐** |
| 5 | 11 | 0.2 MB（实测） | 秒生成 |

> 体积按实测的 **13.4 KB/套**（紧凑 JSON）估算；`layouts/` 里另有一份索引，172 套只有 28 KB。

> 口径说明：套数按**单层**统计 —— 多层住宅（全库 1008 套）只算房间最多的那一层。把两层加一起会虚高（比如四室会从 172 变成 308）。

## 2. 常用参数

```powershell
# 只要 90–140 m² 的（公寓尺度，排除独栋别墅）
node tools/layouts-build.mjs 4 --area=90-140 --clean

# 0 室有 1500 多套，只取面积最小的 200 套
node tools/layouts-build.mjs 0 --top=200 --clean

# 数据放在别处的 CubiCasa5K 目录
node tools/layouts-build.mjs 4 --root=D:\hy\cubicasa5k --clean

# 换门宽先验（尺度推定用；默认 800mm）
node tools/layouts-build.mjs 4 --door=900 --clean
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--area=min-max` | `0-1000` | 套内面积区间（m²），转换后按真实面积过滤 |
| `--top=N` | `0`（全部） | 只写面积最小的 N 套 |
| `--clean` | 关 | 写之前清空 `layouts/*.json` |
| `--root=dir` | `.cache/cubicasa5k` | CubiCasa5K 的 `model.svg` 根目录 |
| `--out=dir` | `layouts` | 输出目录 |
| `--door=mm` | `800` | 单开门宽度先验，用于把像素换算成毫米 |

## 3. 应用里怎么用

**方式 A：用项目自带的零依赖服务器（推荐）**

```powershell
cd D:\hy\floorplan-3d
node tools\serve.mjs 8123
```

打开 **http://127.0.0.1:8123** → `文件 ▾` → **户型库…** → 调筛选 → 点条目直接载入。

**方式 B：Python**

```powershell
cd D:\hy\floorplan-3d
python -m http.server 8080
```

> ⚠️ **别用 8000**。这台机器上 8000 没有进程监听，却被 Windows 保留了，绑定会报
> `PermissionError: [WinError 10013]`（Node 也一样是 `EACCES`）。实测可用端口：**8080 / 8081 / 8123 / 5173 / 3000**。
> 想确认哪些段被保留：`netsh interface ipv4 show excludedportrange protocol=tcp`

⚠️ **必须走 http，不能双击 `index.html`** —— `file://` 页面不允许读本地文件，户型库会提示起服务器。单文件导入（`导入户型 JSON`）不受此限。

筛选框含义：`卧 ≥ / 卫 ≥ / 厅 ≥ / 面积区间`，列表按面积升序，同面积按窗数降序。每行左侧是**平面图缩略图**，直接看形状挑户型。

> **想回到内置的三室两厅两卫？** 用 `文件 ▾ → 重置为默认方案`。
> 该操作会恢复内置几何 + 46 件手写家具（含床/沙发/餐桌）+ 真实承重墙标注 + 手写尺寸链，
> 并清掉"上次载入的户型"存档（所以刷新后也不会退回导入的户型）。
> 内置户型**不来自 CubiCasa5K 数据集**，是项目自带的演示方案，因此不出现在列表里。

### 缩略图

`layouts-thumbs.mjs` 会给每套户型渲染一张平面图缩略图（`layouts/thumb/*.png`，约 2–3 KB/张），
并在 `index.json` 里写入 `thumb` 字段。**`layouts-build.mjs` 在生成户型库后会自动调用它**，不需要单独跑。

需要单独重画时：

```powershell
node tools/layouts-thumbs.mjs              # 只画缺的（快）
node tools/layouts-thumbs.mjs --px=520     # 换更大尺寸
node tools/layouts-thumbs.mjs --force      # 全部重画
```

缩略图用的是和 2D 视图同一套配色：房间按地面材料上色、墙体深色、门橙色、窗浅蓝、家具灰块。

## 4. 这些户型真的都不一样吗？

**是。** 我做了三项重复检测（`tools/cubicasa-dupcheck.mjs`）：

| 判据 | 结果 |
|---|---|
| 样本编号跨风格目录重复 | **0** —— 三个目录是分区：`high_quality_architectural` 3732、`high_quality` 992、`colorful` 276，两两交集全为 0 |
| 墙体几何完全相同（外接框+数量指纹） | 20 组 / 40 套（**0.8%**） |
| 房间构成相同（房型+面积占比，量化到 1%） | 31 组 / 63 套（**1.3%**） |
| **四室及以上 194 套里的重复** | **0 组 / 0 套** |

也就是说：全库约 98% 是独一份的布局；**你现在用的四室库（165 套）里没有重复户型**。

需要复查时：

```powershell
node tools/cubicasa-dupcheck.mjs .cache/cubicasa5k
```

## 6. 常见问题

**Q：换了套数，之前的还能看吗？**
不能 —— 索引被覆盖了。想同时留几套，用 `--out=layouts3` 之类分开存，再把应用里的路径改掉（目前写死 `layouts/`）。

**Q：为什么默认是 4 室、而不是更多？**
四室是"套数够选（172 套）"和"体积够小（2.3 MB）"的平衡点。5 室只有 11 套，3 室要 9 MB —— 都能随时一条命令切过去。

**Q：面积范围怎么设比较合理？**
默认 `0-1000` 会把独栋也算进来（四室最大 351.9 m²）。想要公寓尺度就 `--area=90-160`，能筛掉一多半别墅。

**Q：为什么导入的户型只有一条尺寸线？**
CubiCasa5K 的 SVG 里有尺寸文字，但都是 `style="display:none"` 的英制标注（如 `5'4" x 20'4"`），**不是结构化的分段链**（没有起止位置和分段逻辑）。所以转换器改为**按墙体外沿的断点自动生成**：每边两条 —— 明细链 + 总长链。这是从几何推出来的，不等于原图纸的分段方式。

**Q：为什么承重墙没有红色？**
CubiCasa 只有 `Wall` / `Panel` / `Railing` 三种实体墙，**完全没有承重墙标注**。转换器按几何推断：**贴着外包络的墙标为 `b`（承重，显示红色且禁止拆除）**，内部隔墙标 `n`。这是启发式 —— 真实的承重墙要看结构图，这个数据集里推不出来。

**Q：载入后 3D 是空的？**
对 —— CubiCasa5K 只标注墙/门/窗/房间，家具图标与 `LIB` 的 45 种 `type` 没有对应关系，所以没转家具。可以在应用里拖家具库手动摆。

**Q：房间名为什么有的是"房间""未定义空间"？**
原始标注里 `Undefined`（9033 次）和 `UserDefined` 是最多的两类，CubiCasa 自己也没给语义。转换器把它们映射成"房间"。
