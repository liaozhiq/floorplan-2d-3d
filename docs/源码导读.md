# 户型装修设计 · 源码导读

> 面向要读、要改这个项目的人。所有行号基于 [index.html](../index.html)（2674 行，commit `730ec09`）。

## 0. 先说结论

这不是打包产物，**没有"逆向"这一步**。`index.html` 就是手写的源码：无构建、无压缩、无 sourcemap，`git log` 全部 9 个 commit 里代码文件始终只有它一个。

它的"像产物"来自于**单文件架构**——作者刻意把一个完整应用塞进一个 HTML，靠两段脚本内部再分层。读它的成本不在压缩，而在于：

1. 两段 `<script>` 靠**全局变量**通信，跳转时容易丢线索；
2. 2D 与 3D 各有自己的**渲染栈**，中间只靠 `state` 和 `window.View3D` 这一个对象桥接；
3. 数据（墙体、房间、家具库）和逻辑混在一起。

本文按"数据 → 2D → 交互 → 3D → 时序"的顺序拆开讲。

## 2. 启动时序（为什么它能跑）

经典脚本在 `345` 行位置**立即执行**，模块脚本被自动 defer，且要等 three.js 从 CDN 下载完。所以：

```
解析到 345 ──► 2D 应用同步初始化完成（画面已可用）
                 1504–1507: applyStaticLang → buildDefs → buildLib
                            → renderOpenings → renderDims → fitView → renderAll
解析到 1509 ──► 模块开始拉 three.js（数千行，磁盘缓存后很快）
                 下载完成后才定义 window.View3D
```

**离线后果**：`three.js` 拉不到时模块整体不执行，`window.View3D` 永远是 `undefined`。2D 完全正常；按 `T` 或点「3D 场景」会走 [index.html:1422](../index.html#L1422) 的提示：

```js
if (!window.View3D) return toast(tr('3D 引擎仍在加载或加载失败（需要联网加载 three.js）', ...));
```

这是全项目**唯一的**外部请求，其余资源全部内联。

## 3. 两段脚本的通信契约 ⚠️ 最容易被忽略的地方

模块脚本能直接读到 2D 脚本里的东西，靠的是两条不同的 JS 规则：

| 2D 脚本里的声明形式 | 落到哪里 | 模块里怎么访问 |
|---|---|---|
| `function foo(){}` | 全局对象属性 | `window.foo()` **或** `foo()` |
| `const` / `let`（如 `state`、`ui`、`tr`、`ROOMS`） | 全局**词法**作用域，不在 `window` 上 | 只能写 `foo`，写 `window.foo` 是 `undefined` |

所以模块里会看到两种写法混用，这是有意区分，不是笔误：

- `window.select(...)` / `window.closeDrawers()`（[1619](../index.html#L1619)、[1575](../index.html#L1575)）—— 调 2D 的函数，显式走 window；
- `state` / `ui` / `tr` / `ROOMS` / `esc` / `area` —— 直接引用全局词法变量。

**反方向**：2D 只能通过 `window.View3D` 这一个对象访问 3D，且处处用可选链 `?.`，因为模块可能还没加载。

### `window.View3D` 契约（[2671](../index.html#L2671)）

```js
window.View3D = {
  enter, exit,                                  // async，含过渡动画
  relang,                                       // 语言切换后重建 3D 标签
  sync: () => sync(),                           // 2D 状态变化 → 3D 增量更新
  shot,                                         // 导出 3D 截图为 PNG
  groundAt,                                     // 屏幕坐标 → 地面 mm 坐标
  flyToRoom: id => active && !anim && flyToRoom(id),
  walking: () => active && opt.mode === 'walk',
}
```

`walking()` 被 2D 的键盘处理器用来"漫游时交出键盘控制权"（[1296](../index.html#L1296)）：漫游中 WASD 归 3D，其余 2D 快捷键全部让行。

### 视角切换的三层 class

| class | 加在 | 作用 |
|---|---|---|
| `m3d` | `body` | 工具栏换组、分段控件滑块位移（CSS `121` 行） |
| `is3d` | `#stage` | 2D SVG 淡出、3D canvas 淡入 |
| `animating` | `#stage` | 过渡期间隐藏 3D 提示、锁交互 |
| `busy` | `body` | 防止切换途中重复触发 |

## 4. 数据模型

### 4.1 坐标系

**2D 世界**：单位 mm，原点在左侧外墙内皮 / 顶部外墙内皮，`x` 向右、`y` 向下（屏幕坐标习惯）。户型外包络约 12090 × 10800 mm。

**3D 世界**：单位米，户型中心平移到原点：

```js
const OX = 6000, OY = 5300, H = 2.8;   // 户型中心、层高
const wx = x => (x - OX) / 1000;       // 平面 x → 世界 x
const wz = y => (y - OY) / 1000;       // 平面 y → 世界 z
```

注意 3D 中**平面 y 对应世界 z**，且方向不变（y 增大 → z 增大），所以俯视时画面与 2D 同向。所有 `y = 0` 表示地面，家具模型也统一按"底面在 y=0"建模。

### 4.2 静态数据（户型定义）

| 常量 | 行 | 结构 | 数量 |
|---|---|---|---|
| `WALLS` | [395](../index.html#L395) | `[x0, y0, x1, y1, type]`，轴对齐矩形 | 46 段 |
| `WINS` | [423](../index.html#L423) | `[x0, y0, x1, y1]` | 11 处 |
| `DOORS` | [431](../index.html#L431) | `{name, rect, h, c, o, len, entry?}` | 6 樘 |
| `SLIDES` | [440](../index.html#L440) | `{rect, v}`，`v` 为竖向 | 2 樘 |
| `ROOMS` | [445](../index.html#L445) | `{id, name, poly, mat, at?, counted?}` | 13 间 |
| `MATS` | [460](../index.html#L460) | `key → {name, price, sw}` | 8 种 |
| `LIB` | [471](../index.html#L471) | `[{cat, items:[[type, name, w, d, color]]}]` | 6 类 / 60 件 |

**墙体类型码**（`WALLS[i][4]`）是本项目最需要记的约定：

| 码 | 含义 | 颜色 | 可拆 |
|---|---|---|---|
| `b` | 承重墙 | 黑（开图层时红棕） | ✗ |
| `e` | 外墙 | 灰 | ✗（仅提示不建议） |
| `n` | 非承重隔墙 | 中灰 | ✓ |
| `low` | 矮墙 | 米色描边 | ✓ |

**门的方向约定**（`DOORS`）最容易看懵：`h` 是铰点，`c` 是关门方向，`o` 是开门方向，三者都是**单位向量**，`len` 是门扇长度。2D 画弧和 3D 摆门扇都靠这三个量算出角度：

```js
const ang = v => Math.atan2(-v[1], v[0]);   // 平面向量 → 绕 Y 轴旋转角
const ox = hx + o[0]*L, oy = hy + o[1]*L;   // 2D：门扇打开后的端点
const sweep = o[0]*c[1] - o[1]*c[0] > 0 ? 1 : 0;   // SVG 弧线方向（叉积定顺逆）
```

**飘窗**：`counted: false` 的房间不计入套内面积（[870](../index.html#L870) 的 `filter`），3D 里还额外做成抬高 450mm 的台（`ExtrudeGeometry` depth .45）。

### 4.3 运行期状态

```js
state = {                       // 持久化到 localStorage['huxing-design-v1']
  furniture: [{id, type, name, cx, cy, w, d, rot, color}],
  rooms:     {master: {name, mat}, ...},   // 只存用户可改的：名称 + 地面材料
  demolished:['w12', ...],                 // 墙体下标 → 'w'+i
  measures:  [{a:{x,y}, b:{x,y}}],         // 单位 mm
}
ui    = {tool, sel, mA, mCur, layers}      // 交互态，不持久化
view  = {x0, y0, s}                        // 2D 视口：视左上角 mm + 缩放(mm→px)
opt   = {cut, furn, labels, night, hour, mode}   // 3D 显示选项
```

三个 localStorage key：`huxing-design-v1`（方案）、`huxing-lang`（语言）、`huxing-panes`（侧栏折叠）。

**关键设计**：`state` 里**不存**墙体和房间几何，几何永远来自源码常量，只有"拆了哪面墙"以 id 形式记录。这样改户型只需改 `WALLS`，旧方案不会错位——`fixState()`（[549](../index.html#L549)）也只做字段补全。

### 4.4 撤销栈

快照式，不是命令式：

```js
const snap = () => JSON.stringify(state);
function commit(before){ undoStack.push(before); if (undoStack.length > 150) undoStack.shift(); redoStack.length = 0; save(); }
function mutate(fn){ const b = snap(); fn(); commit(b); renderAll(); }
```

⚠️ 陷阱：`mutate` 会**立即** `renderAll()`。所以拖动家具时**不能**用 `mutate`（每帧全量重绘 + 每帧压栈），拖动路径是：pointerdown 存 `before: snap()` → pointermove 直接改 `state` 并只重绘 `renderFurn()+renderSel()` → pointerup 才 `commit(before)`（[1258](../index.html#L1258)、[1189](../index.html#L1189)）。改交互代码时必须守住这个约定。

## 5. 2D 引擎

### 5.1 全量字符串重绘

2D 没有虚拟 DOM，也没有逐节点更新，**每次都是拼字符串替换 `innerHTML`**：

```js
function renderAll(){
  renderGrid(); renderRooms(); renderFurn(); renderWalls();
  renderLabels(); renderMeasure(); renderSel(); renderPanel(); updateHeader();
  window.View3D?.sync();          // ← 顺带驱动 3D
}
```

对 46 面墙 + 几十件家具，这个量级完全够快，而且省掉所有 diff 代码。

注意哪些**不在** `renderAll` 里：

| 函数 | 何时画 | 原因 |
|---|---|---|
| `renderOpenings` | 启动 + 换语言 | 门窗是静态几何，但含翻译文本 |
| `renderDims` | 启动 + 图层开关 | 尺寸链是常量，切换只改 `display` |
| `renderPanel` | 在 `renderAll` 内 | 面板内容依赖选中项与统计 |

### 5.2 SVG 图层（[306–316](../index.html#L306)）

自下而上：`gGrid` 网格 → `gRooms` 地面 → `gFurn` 家具 → `gWalls` 墙 → `gOpen` 门窗 → `gLabels` 房间名 → `gDims` 尺寸 → `gMeasure` 测量 → `gSel` 选中框。

命中测试**不自己算几何**，而是靠写在元素上的 `data-*` + `closest()`：

```js
t.closest('[data-fid]')    // 家具
t.closest('[data-wall]')   // 墙体（拆改用）
t.closest('[data-room]')   // 房间（点空白处选中房间）
t.closest('[data-handle]') // 旋转 / 缩放把手
```

选中把手是"透明大热区 + 可见小图标"两层叠着画（[849–852](../index.html#L849)），`COARSE` 时热区放大到 24px，解决触屏点不准的问题。

### 5.3 视图变换

只有一个缩放系数和一个平移量，直接喂给 `viewBox`：

```js
svg.setAttribute('viewBox', `${view.x0} ${view.y0} ${W/view.s} ${H/view.s}`);
```

`view.s` 是 **mm → 屏幕 px** 的换算比。比例尺刻度、状态栏上的「1:N」、以及 1:60 / 1:100 两个按钮，全部由它推导：

```js
const PX_MM = 25.4/96;                    // 1 CSS px = 0.2646 mm
ratio = 1 / (view.s * PX_MM);             // 显示成 1:N
setRatio(60) → zoomAt(1/(60*PX_MM), ...)  // 一键 1:60
```

`zoomAt(ns, mx, my)` 是标准"以光标为不动点"的缩放；范围钳在 `0.012 ~ 2`。`fitView()` 用 `BOUNDS`（比户型各方向多留约 1.5m 余量）适配窗口。

窗口尺寸变化用 `ResizeObserver` 处理（[1488](../index.html#L1488)），逻辑值得注意：**首次布局（宽度为 0 → 有值）调 `fitView()`，之后只平移补偿、保持视觉中心不动**，否则收起侧栏时画面会跳。

### 5.4 家具图例 `furnSVG`（[625](../index.html#L625)）

同一个函数同时服务三处：平面图里的家具、左侧库的小图标、拖动时的幽灵图。45 个 `case` 分支，与 `LIB` 里的 45 种 `type` **一一对应、无遗漏**，每种家具用几个 `<rect>/<ellipse>/<path>` 拼出来的俯视符号。工具函数在 [619–623](../index.html#L619)：

```js
const ST = 'stroke="#3d3a34" stroke-width="1" vector-effect="non-scaling-stroke"';
rc(x,y,w,h,fill,extra)   // rect
ec(cx,cy,rx,ry,fill,extra)  // ellipse
ln / pa                  // line / path
```

`vector-effect="non-scaling-stroke"` 是关键：线宽不随 `view.s` 缩放，放大后线条不会变粗。

**加一种新家具**要动三个地方：`LIB` 里加条目 → `furnSVG` 加 case（2D 外观）→ `buildFurniture` 加 case（3D 模型）。用到的 `type` 不在 `furnSVG` 里会画成空白（`switch` 无 `default`）。

## 6. 交互状态机（2D）

一个 `drag` 对象描述所有拖拽，五种 `kind`：

| kind | 触发 | 位移处理 | 结束 |
|---|---|---|---|
| `move` | 按在选择工具的家具上 | `snapMove()` 算中心 | 移动过则 commit |
| `rot` | 按旋转把手 | `atan2`，Shift 自由，否则 15° 步进 | 同上 |
| `size` | 按缩放手柄 | 转到局部坐标，左上角固定，最小 100mm | 同上 |
| `pan` | 按空白处 | 反向平移 `view` | 没移动且松手 → 选中该房间或取消选中 |
| `measure` | 测量工具下按下 | 更新 `ui.mCur` | 有拖动则成线，否则保留起点等第二次点击 |

几个必须知道的常量与标志：

```js
const TAP = COARSE ? 9 : 4;   // 按下后移动超过这么多 px 才算拖动，否则是"点击"
drag.moved                    // 一旦超过 TAP 置 true；轻点家具因此不会抖一下（1256 行注释）
```

### 6.1 双指缩放

触屏另有一套 `touches` Map + `pinch` 状态：第二指落下时**取消**正在进行的单指操作（`endDrag(cancel=true)`），然后以两指中点+距离做缩放平移。双指结束后剩下的那根手指不再触发任何操作（[1276](../index.html#L1276)）。

顺带 `gesturestart/change/end` 全部 `preventDefault`，防止 iPad Safari 把双指当成整页缩放。

### 6.2 吸附

三套逻辑，都在 [1143–1164](../index.html#L1143)：

- **网格**：始终 `Math.round(v/10)*10`，即 10mm 对齐。
- **贴墙（`snapMove`）**：对每个矩形（未拆的墙 + 窗）比较四条边的候选位，取屏幕距离最近的一侧。容差 `10/view.s`——**10 屏幕像素换算成 mm**，所以放大后吸附手感一致。
- **测量点（`snapPoint`）**：单独对 x、y 找最近的墙边；`shift` 时锁定距起点更近的那个轴。

`pushOut()`（[1068](../index.html#L1068)）是"新家具别埋在墙里"：沿穿透更浅的轴推出去，最多迭代 4 次处理墙角。

### 6.3 键盘

集中在 [1294](../index.html#L1294)。三条优先级容易被忽略：

1. 焦点在输入框里 → 全部让行；
2. `window.View3D?.walking()` → 全部让行（WASD 归漫游）；
3. 3D 模式下 `v/m/x/f/+/-` 全部让行（那些是 2D 工具），只留 `t`、`r`、`delete`、方向键、Esc。

### 6.4 家具库拖放

刻意**不用** HTML5 DnD，改用 pointer 事件（[1337](../index.html#L1337) 注释写明：iPad 上 DnD 不可靠）。列表 `touch-action: pan-y` 让竖向滑动仍归浏览器滚动（会触发 `pointercancel` 自动取消拖放），横向拖才创建幽灵图。

幽灵图的尺寸按落点比例实时算：2D 用 `view.s`，3D 用 `groundAt()` 返回的 `s`（该处每 mm 的屏幕像素），所以 3D 里近大远小是对的。

## 7. 3D 引擎

### 7.1 一次性初始化

`init()`（[1536](../index.html#L1536)）只跑一次（`inited` 守卫），之后进出 3D 只是开关渲染循环。内容包括：WebGLRenderer（ACES tone mapping + PCF 软阴影）、CSS2DRenderer、PerspectiveCamera(FOV 45)、OrbitControls、PointerLockControls、半球光 + 平行光、160m 地面、PMREM 环境贴图。

**按设备降级**：`COARSE` 时阴影像素从 4096 降到 2048（[1559](../index.html#L1559) 注释："平板 GPU 用小一点的阴影贴图"）。

### 7.2 五个 Group 的分工

| Group | 内容 | 动画属性 |
|---|---|---|
| `archFloor` | 地面、门洞门槛 | 不参与升起 |
| `archUp` | 墙、窗、门扇、天花、过梁 | `scale.y = grow` |
| `furnG` | 全部家具 | `scale.y = furnGrow` |
| `labelG` | CSS2D 房间标签 | 淡入淡出 |
| `lampG` | 吸顶灯盘 + 点光源 | `grow > .99` 才显示 |

**"墙体从地面升起"的实现**就是 `archUp.scale.y` 从 0 到 1——因为所有几何都按真实高度建模且底面在 y=0，压缩 Y 轴天然得到"升起"效果。家具用独立的 `furnGrow` 错开时序。这是全项目最取巧的一处，`applyGrow()`（[2387](../index.html#L2387)）只有 4 行。

### 7.3 材质系统

`mat(color, opts)`（[1633](../index.html#L1633)）带缓存，key 是 `color + JSON(opts)`。缓存里有两条策略：

- 只在 `metalness > 0` 或 `roughness < .4` 的材质上挂 `envMap`（避免哑光墙面整体变亮）；
- 每个材质的基准反射强度存进 `m.userData.env`，夜景时统一乘以 `envK`（[2405](../index.html#L2405)）——这样切换夜景不用重建材质。

地面贴图是**运行时用 canvas 画的**（`floorMat`，[1653](../index.html#L1653)）：木地板的板缝与木纹、大理石的贝塞尔纹路、水磨石的随机石子、瓷砖的勾缝，全部程序生成，无外部图片。关键一句：

```js
t.repeat.set(1/s.sx, 1/s.sy);   // UV 单位是米，所以 repeat = 1/单片尺寸
```

因为 `ShapeGeometry` 的 UV 直接等于造型坐标（本项目里就是米），这样一改就能让"800 地砖"真的每 0.8m 一块。

### 7.4 几何工具

[1690–1745](../index.html#L1690) 一组声明式小工具，**约定 y = 底面高度**（不是中心），所以 `box(w,h,d,m,x,y,z)` 内部做了 `y + h/2`：

```js
box / rbox(圆角) / cyl / lathe / rod / tube / blob / ring / shell / legs
```

`rbox` 用 three 的 `RoundedBoxGeometry`，家具几乎全靠它做出圆角，这是"精细感"的主要来源。加上一批语义化材质工厂：`metal / chrome / hwMat / blackMetal / mirror / ceramic / screenMat / glowMat`。

### 7.5 家具建模 `buildFurniture`（[1787](../index.html#L1787)）

约 490 行、45 个 `case`，是本文件最长的一段，覆盖的 `type` 与 2D 的 `furnSVG` 完全相同。约定：

- **局部坐标**：`z = -d/2` 是背面，靠背朝 `-z`；`y = 0` 是地面。
- 尺寸来自 `f.w / f.d`（毫米）经 `M()` 转米，所以**同一段代码能画出 1.5m 和 1.8m 的床**，不需要两套模型。
- 确定性随机：`rng(Math.round(f.w*7 + f.d*13 + f.cx + f.cy))` —— 种子由家具尺寸和位置决定，所以**同一个位置永远是同一件家具**（抱枕的歪斜角度不会每次刷新都变），挪动位置时才会换一种"随意感"。

细节量举例（`case 'bed'`）：内缩踢脚 + 床箱 + 床头板 + 竖向软包（按宽度自动算块数）+ 床垫 + 被子 + 翻边 + 床尾巾 + 枕头。这是"柜门分缝与拉手、软包床头"这类 README 卖点的实现处。

### 7.6 建筑 `buildArch`（[2290](../index.html#L2290)）

一次重建全部建筑几何，顺序是：房间地面（飘窗做 450mm 台）→ 天花（`flip` 让法线朝下，只在室内可见）→ 吸顶灯 + 点光源 → 门洞门槛 → 墙体（`wallBox`）→ 门窗洞上方过梁 → 窗（玻璃 + 竖梃 + 上下框）→ 平开门（可旋转的 `pivot`）→ 推拉门。

两个副产品数组：

```js
colliders = [[x0, z0, x1, z1], ...]   // 米，漫游碰撞用（墙 + 窗）
doors     = [{pivot, a0, a1, open, cur}]  // a0/a1 关/开角，cur 当前角（每帧插值）
```

`wallBox`（[2276](../index.html#L2276)）还顺手生成**漫游辅助**：墙体棱线（`EdgesGeometry`）+ 踢脚线，都标 `userData.walkOnly = true`，只在漫游模式显示——这就是 commit `2d9f18b` 说的"显示墙体棱线和踢脚线以区分相邻墙面和墙角"。

墙顶材质单独用 `capMat`（深色）：BoxGeometry 的材质数组第 3 项对应 `+y` 面，剖切墙俯视时能靠深色顶面读出墙的位置。

### 7.7 增量同步

2D 每次 `renderAll` 都会调 `sync()`，但 3D 不该跟着全量重建，于是用**序列化签名**做脏检查（[2377](../index.html#L2377)）：

```js
const a = JSON.stringify([state.rooms, state.demolished, opt.cut]);  // → buildArch
const f = JSON.stringify(state.furniture);                           // → buildFurn
const l = JSON.stringify([state.rooms, opt.cut]);                    // → buildLabels
```

只有签名变了才重建对应部分。所以拖动家具时 3D 不会每帧重建；而 `state.rooms` 里改了地面材料 → 三个签名全变 → 全量重建（这是正确且必要的）。

### 7.8 相机：2D 与 3D 的"视觉接缝"

`planPose()`（[2415](../index.html#L2415)）是整个 2D↔3D 过渡能成立的核心。它要构造一个**与当前 2D 视口完全重合的正俯视位姿**：

```js
const cx = view.x0 + SW()/2/view.s;        // 2D 视口中心的 mm 坐标
const visH = SH()/view.s/1000;             // 该视口看到的高度（米）
const dist = visH/2 / Math.tan(FOV/2*Math.PI/180);   // 透视相机要退多远才装得下
```

即：**用 2D 的缩放反推 3D 相机高度**。因为透视相机在距离 `d` 处，垂直可视高度 = `2·d·tan(FOV/2)`，反解 `d` 就能让 3D 地面与 2D 平面逐像素对齐。之后 `isoFrom()` 沿固定方向 `(.3,.82,.49)` 把相机拉成斜视，就得到"从平面图里立起来"的错觉。

`camTween`（[2428](../index.html#L2428)）用**球坐标插值**而非直线插值：目标点线性插值、半径/俯仰/方位角分别插值，方位角取最短弧。这样镜头是沿弧线环绕的，不会穿过房子。

### 7.9 进出 3D 的时间轴

`enter()`（[2449](../index.html#L2449)）：

```
sync(true) 全量建场景
setPose(planPose)  →  camera 与 2D 完全重合
stage.classList.add('is3d')   ← 交叉淡入点
await 420ms                    ← 让淡入完成，此时看起来还没变化
animate(1700ms):
  camTween(A→B)  ease(t/.85)      镜头倾斜环绕
  grow      ease((t-.1)/.55)       墙体从第 10% 开始升起
  furnGrow  ease((t-.45)/.5)       家具从第 45% 才开始立起
```

`exit()` 完全反向：家具先收起 → 墙体下沉 → 镜头回到正俯视 → 摘掉 `is3d` → 等 450ms 淡出 → 停 rAF。**摘 class 的时机必须在相机已经压平之后**，否则会看到 3D 画面跳一下。

### 7.10 拾取与地面投影

`pick(e)`（[2489](../index.html#L2489)）沿射线取第一个命中，按优先级返回 `{door,dist}` / `{room}` / `{fid}` / `null`：

- 玻璃（`glassMat`）直接跳过，否则窗会挡住室内；
- 命中墙体等无 `userData` 的对象 → **返回 null**（"被墙挡住"，注释 [2501](../index.html#L2501)），所以点在墙上不会误选墙后的家具。

`groundAt(x, y)`（[2507](../index.html#L2507)）把屏幕点投到 `y=0` 平面，返回 `{x, y, s}`（mm 坐标 + 该处每 mm 的屏幕像素）。它多做了一件事：如果视线**先**碰到墙体，落点取墙上的点而不是穿墙后的地面——避免拖家具时"穿墙"。

### 7.11 漫游

桌面端 `PointerLockControls` 锁鼠标；iPad 不支持指针锁，退回到**虚拟摇杆**（`bindJoystick`）。`pointerlockerror` 也会自动退回摇杆（[2635](../index.html#L2635)）。

移动与碰撞（[2587](../index.html#L2587)）：

```js
speed = Shift ? 2.6 : 1.4  m/s
分轴判定：x、z 分别试探，允许沿墙滑动（而不是撞墙停死）
blocked(x,z,r=.22):
  colliders 矩形外扩 r 命中 → true
  每扇门：把门扇当作线段做点到线段距离，< r*.8 → true   ← 门开着会真的挡住
```

门扇碰撞用门的**当前转角**实时算端点，所以开门后能走过去、关门就走不过去。

### 7.12 光照与夜景

`applyLight()`（[2395](../index.html#L2395)）把 7:00–18:00 的滑块映射成太阳方位角与高度角，色温随高度变化。夜景是整体切换：太阳降到 0.05、半球光 0.12、天空与地面换深色、每个房间的点光源点亮到 6、曝光提到 1.25、环境反射降到 `envK = .15`。

## 8. 三条关键时序

### 8.1 2D 拖动一件家具

```
pointerdown  按在 [data-fid] 上
  select({kind:'furn'}) → renderSel + renderPanel
  drag = {kind:'move', ox, oy, before: snap(), moved:false}

pointermove  超过 TAP 才置 moved
  snapMove() 算中心（10mm 网格 → 贴墙优先）
  renderFurn() + renderSel()          ← 只重绘这两个图层，不压栈

pointerup
  endDrag() → commit(drag.before) → renderAll()
    └─ window.View3D?.sync()
         └─ 家具签名变了 → buildFurn() 全量重建 3D 家具
```

### 8.2 切到 3D

```
setView('3d')
  body.m3d  → 工具栏换组、"正在切换"锁 UI
  await View3D.enter()
    init()（首次）
    sync(true) → buildArch + buildFurn + buildLabels
    setPose(planPose())        与 2D 逐像素重合
    #stage.is3d                交叉淡入
    420ms 后开始 1700ms 动画   镜头倾斜 + 墙升起 + 家具立起

之后任何 2D 改动 → renderAll → sync() 签名脏检查 → 局部重建
```

### 8.3 3D 里拖动家具

3D 的拖拽监听挂在 `host` 的**捕获阶段**（[1587](../index.html#L1587)），先于 OrbitControls，并在命中已选家具时 `orbit.enabled = false`——否则会一边拖家具一边转镜头。

```
pointerdown(capture)
  pick() 命中 ui.sel 的家具 && groundAt() 有落点
  fdrag = {...}; orbit.enabled = false
pointermove
  groundAt() → snapMove() → 直接改 furnG 里那个模型的 position（不重建）
pointerup
  commit() → renderAll() → 全量对齐 2D
```

## 10. 坑与约束

1. **必须联网**才能进 3D（CDN importmap）。这是唯一外部依赖。
2. **`type="module"` + `file://` 的 CORS**：importmap 解析拿的是 https 地址，一般可用；但部分浏览器在 `file://` 下限制更严，README 建议起静态服务器。
3. **2D 与 3D 的坐标系差异**是改代码时最常见的 bug 源：2D 是 mm + 右手向下，3D 是米 + 中心原点。写几何逻辑前先看 `wx/wz/M`。
4. **漫游时 2D 快捷键全让行**，`walking()` 是唯一开关。
5. **拖动中不要用 `mutate()`**（会每帧压栈 + 全量重绘）。
6. **`sync()` 的签名全是 `JSON.stringify`**，家具数量极大时会有性能上限（几千件量级才会明显）。
7. **撤销栈存整份 `state` 的 JSON**，上限 150 步。家具多时内存占用随之上升。
8. **CSS2DRenderer 的标签不继承父级 visible**，必须逐个设置（`showLabels`，[2386](../index.html#L2386) 注释写明）。
9. **`NOLABEL`** 列表里的家具不显示名称文字，判定还叠加了"最小边 ≥ 380mm"（[741](../index.html#L741)），避免小家具上糊一团字。
10. **改 `furnSVG` 时注意 `switch` 没有 `default`**，漏写 case 会静默画出空白。

## 12. 一句话总结架构

> **一份 `state` + 一堆常量数据，2D 用字符串重绘 SVG，3D 用 three 重建 mesh，两边靠 `sync()` 的签名脏检查对齐；视角切换靠"用 2D 缩放反推 3D 相机高度"做到视觉无缝。**
